# PhotoMap — фото-карта и просмотр фотопутей

PhotoMap — локальный инструмент для построения карты по геометкам фотографий. Python-скрипт рекурсивно читает папку с изображениями, извлекает доступные дату и GPS-координаты, группирует снимки по годам и записывает JSON. HTML-карта показывает точки на Яндекс Картах; со страницы точки можно перейти к навигации по снимкам соответствующего псевдопути.

> **Важно о приватности.** Файлы `points_<год>.json` содержат имена файлов, даты и координаты. Не публикуйте их в открытом репозитории или на общедоступном сайте, если это раскрывает личные данные. Для приватного хранения используйте приватный репозиторий и проверяйте, какие файлы добавляете в Git.

## Состав проекта

- `photo_map.py` — сканирование файлов, чтение метаданных, формирование приблизительных точек без GPS и построение псевдопутей.
- `map.html` — клиентская карта, загрузка JSON выбранного года, маркеры и линии маршрутов.
- `photo-path.html` — страница одного псевдопути: предпросмотр файла (если браузер поддерживает формат), ссылка на оригинал, дата, координаты и переход к предыдущему/следующему снимку.
- `points_<год>.json` — создаваемый скриптом файл данных для одного года, например `points_2025.json`. Генерируется при запуске, не является исходным кодом.
- `ico/` — папка с миниатюрами фотографий, создаваемая скриптом при сканировании. Генерируется при запуске, не является исходным кодом.
- `photo_map.log` — журнал работы: ошибки и предупреждения с датой и временем. Дописывается при каждом запуске.
- `test_run/` — результаты пробного прогона (`--test`): свои JSON, `ico/` и лог, чтобы не затирать боевые данные.

Все три исходных файла и JSON, который нужно отобразить, должны находиться в одной папке. Пути к фотографиям в JSON относительны к папке, переданной скрипту; для корректных ссылок обычно следует открывать карту из этой же папки. Папка `ico/` должна лежать рядом с `map.html` — тогда превью миниатюр открывается по относительным ссылкам из JSON.

## Требования

- Python 3.9 или новее.
- Pillow (`PIL`). Установка: `python -m pip install Pillow`.
- Для HEIC/HEIF может понадобиться дополнительный Pillow-плагин `pillow-heif` (см. раздел об ограничениях ниже). Скрипт подключает его автоматически, если он установлен, и предупреждает, если нет: без плагина HEIC/HEIF попадают в журнал ошибок как `cannot identify image file`.
- Браузер с JavaScript и сетевым доступом к API Яндекс Карт.

## Запуск

Запустите генератор, указав каталог фотографий:

```bash
python photo_map.py "путь/к/папке-с-фотографиями"
```

**Без аргумента сканируется папка по умолчанию** — `D:\YandexDisk\Альбомы по годам`. Изменить её можно константой `DEFAULT_PHOTO_DIR` в начале `photo_map.py`. Если папки нет, скрипт сообщит об этом и завершится с кодом 1, ничего не создавая:

```
❌ Папка не найдена: D:\YandexDisk\Альбомы по годам
   Это папка по умолчанию (D:\YandexDisk\Альбомы по годам).
   Укажите путь явно:  python photo_map.py "D:\путь\к\фотографиям"
   Или текущую папку:  python photo_map.py .
```

Текущая папка сканируется при явном `.`: `python photo_map.py .`

По завершении появятся JSON-файлы `points_<год>.json` рядом с корнем, переданным скрипту, и папка `ico/` с миниатюрами.

Дополнительные ключи запуска:

| Ключ | Назначение |
|---|---|
| `--thumbs-dir ПАПКА` | Куда складывать миниатюры. По умолчанию — `<корень>/ico`. |
| `--thumb-size N` | Максимальный размер миниатюры по ширине и высоте в пикселях. По умолчанию `240`. |
| `--no-thumbs` | Не создавать миниатюры (быстрее на больших коллекциях). |
| `--force-thumbs` | Пересоздать миниатюры, даже если файлы уже есть. |
| `--log ФАЙЛ` | Свой путь журнала. По умолчанию — `<корень>/photo_map.log`. |
| `--test [N]` | Пробный прогон: не более `N` файлов (по умолчанию `1000`), результаты в `test_run/`. |

### Журнал ошибок

Все ошибки и предупреждения пишутся в `photo_map.log` рядом с JSON — с датой, временем и полным путём к файлу:

```
===== Запуск 2026-10-18 17:23:44 =====
[2026-10-18 17:23:52] ВНИМАНИЕ HEIC/HEIF не декодируется установленной Pillow: ...
[2026-10-18 17:23:52] ОШИБКА Не удалось создать миниатюру D:\Фото\2025\IMG_0001.HEIC: cannot identify image file '...'
[2026-10-18 17:24:03] ОШИБКА Не удалось прочитать метаданные D:\Фото\2025\IMG_0002.HEIC: cannot identify image file '...'
[2026-10-18 17:25:10] Итог: файлов 12036, ошибок 812, предупреждений 1, время 754.3 с
```

Файл **дописывается**, поэтому история прогонов сохраняется; каждый запуск отделён заголовком. В консоль дублируются только первые 5 ошибок, чтобы тысяча неподдерживаемых HEIC не забивала экран.

### Пробный прогон `--test`

```bash
python photo_map.py "D:\YandexDisk\new1" --test        # первые 1000 файлов
python photo_map.py "D:\YandexDisk\new1" --test 200    # первые 200 файлов
```

Пробный прогон читает не более `N` файлов и складывает всё в подпапку `test_run/`: свои `points_<год>.json`, свои миниатюры `test_run/ico/`, свой лог и копии `map.html`/`photo-path.html`. Боевые JSON и миниатюры не перезаписываются, поэтому `--test` безопасно запускать на реальной коллекции. Результат можно открыть сразу:

```bash
cd "D:\YandexDisk\new1"
python -m http.server 8000
# http://localhost:8000/test_run/map.html
```

Для просмотра используйте HTTP-сервер, а не `file://`: браузеры часто запрещают `fetch()` локальных JSON-файлов из HTML.

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000/map.html`. В поле «Год» укажите год из имени JSON-файла, например `2025`. Год можно передать параметром: `http://localhost:8000/map.html?year=2025`.

## Архитектура и поток данных

### 1. Сканирование и извлечение метаданных

`photo_map.py` рекурсивно обходит дерево каталогов (`os.walk`) и выбирает расширения `.jpg`, `.jpeg`, `.tif`, `.tiff`, `.webp`, `.png`, `.heic`, `.heif` без учёта регистра. Для каждого найденного файла вызывается `get_metadata()`.

Метаданные читаются через Pillow:

1. Дата выбирается по приоритету EXIF-тегов `DateTimeOriginal` (`0x9003`), `DateTimeDigitized` (`0x9004`) и `DateTime` (`0x0132`). Важная деталь: `0x9003` и `0x9004` лежат в **Exif-подкаталоге** (`0x8769`), а `0x0132` — в основном IFD. Читаются оба места, иначе дата почти всегда терялась бы и подменялась на `mtime`. Даты с долями секунды и смещением часового пояса тоже разбираются.
2. GPS берётся из GPS IFD EXIF (`0x8825`): широта и долгота преобразуются из градусов, минут и секунд в десятичные координаты с учётом направлений N/S/E/W.
3. Если координат EXIF нет, выполняется попытка найти широту и долготу в XMP. Извлечение использует регулярные выражения по именам `Latitude` и `Longitude`, поэтому зависит от конкретного формата XMP и не является универсальным XMP-парсером. Дату при отсутствии EXIF тоже пробуем взять из XMP (`exif:DateTimeOriginal`, `photoshop:DateCreated`, `xmp:CreateDate`).
4. Если дата съёмки отсутствует или не распознана, используется время последнего изменения файла (`mtime`). Это может быть дата копирования/редактирования, а не дата съёмки.
5. Координатная пара `0, 0` считается отсутствующей.

Ошибки чтения метаданных пишутся в журнал `photo_map.log`; скрипт продолжает обработку остальных файлов.

### 2. Группировка и приблизительные точки

Снимки группируются по году полученной даты. Файлы без распознанной даты относятся к группе `unknown`.

Для снимков без GPS ищется ближайший по времени снимок с GPS в той же годовой группе. Если разница строго меньше 30 минут, создаётся приблизительная точка рядом с GPS-точкой. Смещение случайное, около `0.001` градуса (порядка сотни метров), масштабируется по временной близости и имеет нижний предел. Такая координата **не является реальным местом съёмки**. В JSON она отмечена `"fake": true`, а на карте обозначена отдельным цветом.

Поиск ближайшего снимка сейчас перебирает все GPS-снимки для каждого файла без координат. Внутри одного года это имеет сложность порядка `O(N × M)` и может стать медленным для очень больших архивов; оптимизация через сортировку по времени и бинарный поиск возможна отдельно.

### 3. Формат JSON

Каждый год записывается отдельным объектом:

```json
{
  "points": [
    {
      "lat": 55.75,
      "lon": 37.61,
      "file": "2025/photo.jpg",
      "timestamp": "2025-05-15T14:30:00",
      "fake": false,
      "thumb": "ico/2025/photo.jpg"
    }
  ],
  "paths": [[0, 1, 2]]
}
```

`points` — точки, отсортированные по ISO-дате. `paths` — массив сегментов; значения в сегменте являются индексами элементов в `points`. Индексы важны: HTML использует их для построения линий и для перехода со страницы карты к нужному псевдопути.

`thumb` — путь к миниатюре относительно папки с `map.html` (по умолчанию `ico/...`). Поле появляется только если миниатюра создана; при `--no-thumbs` его нет. Старые JSON без этого поля продолжают работать: превью просто не показывается.

### 4. Миниатюры

При сканировании скрипт создаёт уменьшенные копии исходных изображений в папке `ico` рядом с JSON-файлами.

- Размер — **не более 240 пикселей по ширине и высоте**; пропорции сохраняются, увеличения маленьких файлов не происходит.
- Структура папок **повторяет исходную**: `photos/2025/day1/photo.jpg` → `ico/2025/day1/photo.jpg`.
- Формат всегда JPEG: миниатюра должна открываться браузером даже тогда, когда исходник — HEIC, TIFF или PNG.
- Ориентация из EXIF учитывается, прозрачность заливается белым.
- Если в папке есть файлы с одинаковым именем, но разными расширениями (`a.jpg` и `a.png`), к имени миниатюры добавляется исходное расширение: `a_jpg.jpg` и `a_png.jpg`.
- **Уже существующие миниатюры не пересоздаются** — повторный запуск обрабатывает только новые файлы и работает на порядок быстрее. Пересобрать всё принудительно: `--force-thumbs`.
- Каждые **500 пропущенных** миниатюр выводится сообщение, что они уже готовы:

  ```
  ♻️  Пропущено уже готовых миниатюр: 500 (не пересоздаются)
  ♻️  Пропущено уже готовых миниатюр: 1000 (не пересоздаются)
  ```

  Строки пишутся и в журнал, чтобы по логу было видно, что запуск был инкрементальным.
- Прогресс выводится шагами по 5% от ожидаемого количества: `⏳ Миниатюры: 15% (150 из 1000)`.
- Если файл не удалось открыть или декодировать, миниатюра для него не создаётся, в журнал пишется строка с причиной, обработка продолжается.
- Папки `ico/` и `test_run/` исключаются из сканирования — их содержимое никогда не считается исходными фотографиями.

### 5. Правило построения псевдопутей

Пары рассматриваются последовательно после сортировки точек по времени. Соседние точки соединяются, только если одновременно:

- временной интервал неотрицательный и **строго меньше 1 часа**;
- расстояние по формуле гаверсинуса между координатами **строго меньше 1 000 метров**.

Если хотя бы одно условие не выполнено, текущий сегмент завершается, и следующая точка начинает новый сегмент. В `paths` сохраняются только сегменты минимум из двух точек. Это псевдопуть, построенный по временной и географической близости; он не доказывает фактический порядок движения или непрерывность маршрута.

### 6. HTML-клиент

`map.html` загружает `points_<год>.json` через `fetch`, проверяет координаты и отображает маркеры с кластеризацией Яндекс Карт. Для каждой точки доступна ссылка на файл и ссылка, открывающая `photo-path.html` с параметрами года и индекса точки. На карте отображаются линии по сегментам `paths`.

**Превью по наведению.** При наведении на маркер или на открытый балун рядом с курсором всплывает миниатюра фотографии (не более 240 px) с подписью — именем файла. Показывается всегда **ровно одна** миниатюра: своя у точки; если её нет — первая миниатюра из того же псевдопути; если и её нет — одна случайная миниатюра загруженного года. Превью скрывается, когда курсор уходит с балуна или маркера, либо когда балун закрывается.

**Группы фото в одной точке.** Когда несколько снимков попадают в одну геоточку, карта показывает кластер с числом, и отдельной метки с миниатюрой нет. Чтобы превью работало и там, наведение на кластер **разворачивает его в отдельные миниатюры**:

- до **30** снимков раскладываются кольцами вокруг значка (8 + 12 + 10) в экранных пикселях, поэтому раскладка не зависит от масштаба;
- у каждой миниатюры видно само фото; наведение даёт крупное превью, клик открывает обычный балун с датой, координатами и ссылкой на псевдопуть;
- значок кластера остаётся на месте, а разнесённые миниатюры — отдельные объекты и в кластеризации не участвуют;
- курсор ушёл с группы и миниатюр — через полсекунды они сворачиваются; смена масштаба или загрузка другого года сворачивают сразу;
- если в группе **больше 30** снимков, разворота нет: внизу появляется подсказка увеличить масштаб.

Реализация: **у `Clusterer` нет события `mouseenter`** (на уровне кластеризатора доступны только `hintopen`/`hintclose` и `balloonopen`/`balloonclose`), поэтому метод `createCluster(center, geoObjects)` переопределяется: у каждого созданного кластера сохраняется состав и вешаются собственные `mouseenter`/`mouseleave`. Смещение точек — через проекцию карты (`toGlobalPixels`/`fromGlobalPixels`) с запасным расчётом «градусов на пиксель». Подсказка кластера отключена (`clusterHasHint: false`), чтобы не перекрывать развёрнутые миниатюры.

`photo-path.html` загружает тот же JSON, находит путь, содержащий индекс выбранной точки, и показывает его снимки последовательно. Навигация доступна кнопками и клавишами ←/→. Если точка не входит в сегмент (например, нет подходящей пары), страница показывает только её. Изображение отображается, если формат поддержан браузером; ссылка на исходный файл остаётся доступной.

HTML-файлы используют внешний API Яндекс Карт. Поэтому для карты требуется интернет; доступность API и требования к ключу зависят от настроек/условий Яндекса и окружения. В клиентском коде предусмотрена обработка неудачной загрузки JSON.

## Известные ограничения и ошибки обработки HEIC/HEIF

Поддержка расширения в списке файлов **не гарантирует**, что Pillow сможет декодировать сам файл. HEIC/HEIF — контейнерные форматы, кодеки и варианты метаданных в них различаются. В стандартной установке Pillow часто не умеет открывать HEIC/HEIF, поэтому возможны ошибки `UnidentifiedImageError`, сообщения об отсутствии декодера или ситуация, когда EXIF/XMP недоступны. Тогда GPS/дата не извлекаются; дата может перейти на `mtime`, а точка — попасть в категорию без GPS.

Рекомендуемый вариант — установить плагин и зарегистрировать его до открытия изображений:

```bash
python -m pip install pillow-heif
```

В начале `photo_map.py` после импорта Pillow добавьте:

```python
from pillow_heif import register_heif_opener
register_heif_opener()
```

Поддержка зависит от версии `pillow-heif`, Pillow и библиотек декодирования, доступных для вашей ОС. На Windows могут потребоваться совместимые бинарные колёса/зависимости. Некоторые HEIC-файлы содержат метаданные в нестандартном месте или без доступных EXIF-тегов; установка плагина сама по себе не гарантирует извлечение GPS и даты. Для проверки сначала запустите обработку на нескольких примерах HEIC и изучите предупреждения в stderr.

Также браузер может не показывать HEIC как изображение даже при успешном чтении метаданных Python. В этом случае исходный файл доступен по ссылке, но для превью потребуется преобразовать копию снимка в JPEG либо использовать браузер с поддержкой HEIC.

## Другие ограничения и рекомендации

- В коде отключён лимит Pillow `Image.MAX_IMAGE_PIXELS` для панорам. Это позволяет открывать очень большие изображения, но снимает защиту от чрезмерного расхода памяти; обрабатывайте только доверенные файлы.
- Псевдокоординаты генерируются случайно, поэтому при повторной генерации могут измениться.
- Ссылки на фото работают, если каталог снимков доступен браузеру по HTTP и структура каталогов совпадает с относительными путями в JSON. Для удалённого GitHub Pages локальные фотографии автоматически не загружаются; их нужно отдельно публиковать и учитывать приватность/объём.
- `map.html` и JSON должны обслуживаться одним локальным HTTP-сервером; `file://` не подходит для `fetch`.
- Координаты проверяются в HTML перед отображением, но JSON считается локальным доверенным входом. Не размещайте непроверенные данные и пользовательские файлы на публичном сервере без дополнительной защиты.
