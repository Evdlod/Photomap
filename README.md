# PhotoMap — фото-карта и просмотр фотопутей

PhotoMap — локальный инструмент для построения карты по геометкам фотографий. Python-скрипт рекурсивно читает папку с изображениями, извлекает доступные дату и GPS-координаты, группирует снимки по годам и записывает JSON. HTML-карта показывает точки на Яндекс Картах; со страницы точки можно перейти к навигации по снимкам соответствующего псевдопути.

> **Важно о приватности.** Файлы `points_<год>.json` содержат имена файлов, даты и координаты. Не публикуйте их в открытом репозитории или на общедоступном сайте, если это раскрывает личные данные. Для приватного хранения используйте приватный репозиторий и проверяйте, какие файлы добавляете в Git.

## Состав проекта

- `photo_map.py` — сканирование файлов, чтение метаданных, формирование приблизительных точек без GPS и построение псевдопутей.
- `map.html` — клиентская карта, загрузка JSON выбранного года, маркеры и линии маршрутов.
- `photo-path.html` — страница одного псевдопути: предпросмотр файла (если браузер поддерживает формат), ссылка на оригинал, дата, координаты и переход к предыдущему/следующему снимку.
- `points_<год>.json` — создаваемый скриптом файл данных для одного года, например `points_2025.json`. Генерируется при запуске, не является исходным кодом.

Все три исходных файла и JSON, который нужно отобразить, должны находиться в одной папке. Пути к фотографиям в JSON относительны к папке, переданной скрипту; для корректных ссылок обычно следует открывать карту из этой же папки.

## Требования

- Python 3.9 или новее.
- Pillow (`PIL`). Установка: `python -m pip install Pillow`.
- Для HEIC/HEIF может понадобиться дополнительный Pillow-плагин `pillow-heif` (см. раздел об ограничениях ниже).
- Браузер с JavaScript и сетевым доступом к API Яндекс Карт.

## Запуск

Перейдите в папку проекта/данных и запустите генератор, указав каталог фотографий:

```bash
python photo_map.py "путь/к/папке-с-фотографиями"
```

Если аргумент не передан, скрипт обрабатывает текущую папку. По завершении появятся JSON-файлы `points_<год>.json` рядом с корнем, переданным скрипту.

Для просмотра используйте HTTP-сервер, а не `file://`: браузеры часто запрещают `fetch()` локальных JSON-файлов из HTML.

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000/map.html`. В поле «Год» укажите год из имени JSON-файла, например `2025`. Год можно передать параметром: `http://localhost:8000/map.html?year=2025`.

## Архитектура и поток данных

### 1. Сканирование и извлечение метаданных

`photo_map.py` рекурсивно обходит дерево каталогов (`os.walk`) и выбирает расширения `.jpg`, `.jpeg`, `.tif`, `.tiff`, `.webp`, `.png`, `.heic`, `.heif` без учёта регистра. Для каждого найденного файла вызывается `get_metadata()`.

Метаданные читаются через Pillow:

1. Дата выбирается по приоритету EXIF-тегов `DateTimeOriginal` (`0x9003`), `DateTimeDigitized` (`0x9004`) и `DateTime`/дата изменения EXIF (`0x0132`).
2. GPS берётся из GPS IFD EXIF (`0x8825`): широта и долгота преобразуются из градусов, минут и секунд в десятичные координаты с учётом направлений N/S/E/W.
3. Если координат EXIF нет, выполняется попытка найти широту и долготу в XMP. Извлечение использует регулярные выражения по именам `Latitude` и `Longitude`, поэтому зависит от конкретного формата XMP и не является универсальным XMP-парсером.
4. Если дата съёмки отсутствует или не распознана, используется время последнего изменения файла (`mtime`). Это может быть дата копирования/редактирования, а не дата съёмки.
5. Координатная пара `0, 0` считается отсутствующей.

Ошибки чтения метаданных выводятся в stderr; скрипт продолжает обработку остальных файлов.

### 2. Группировка и приблизительные точки

Снимки группируются по году полученной даты. Файлы без распознанной даты относятся к группе `unknown`.

Для снимков без GPS ищется ближайший по времени снимок с GPS в той же годовой группе. Если разница строго меньше 30 минут, создаётся приблизительная точка рядом с GPS-точкой. Смещение случайное, около `0.001` градуса (порядка сотни метров), масштабируется по временной близости и имеет нижний предел. Такая координата **не является реальным местом съёмки**. В JSON она отмечена `"fake": true`, а на карте обозначена отдельным цветом.

Поиск ближайшего снимка сейчас перебирает все GPS-снимки для каждого файла без координат. Внутри одного года это имеет сложность порядка `O(N × M)` и может стать медленным для очень больших архивов; оптимизация через сортировку по времени и бинарный поиск возможна отдельно.

### 3. Формат JSON

Каждый год записывается отдельным объектом:

```json
{
  "points": [
    {
      "lat": 55.75,
      "lon": 37.61,
      "file": "2025/photo.jpg",
      "timestamp": "2025-05-15T14:30:00",
      "fake": false
    }
  ],
  "paths": [[0, 1, 2]]
}
```

`points` — точки, отсортированные по ISO-дате. `paths` — массив сегментов; значения в сегменте являются индексами элементов в `points`. Индексы важны: HTML использует их для построения линий и для перехода со страницы карты к нужному псевдопути.

### 4. Правило построения псевдопутей

Пары рассматриваются последовательно после сортировки точек по времени. Соседние точки соединяются, только если одновременно:

- временной интервал неотрицательный и **строго меньше 1 часа**;
- расстояние по формуле гаверсинуса между координатами **строго меньше 1 000 метров**.

Если хотя бы одно условие не выполнено, текущий сегмент завершается, и следующая точка начинает новый сегмент. В `paths` сохраняются только сегменты минимум из двух точек. Это псевдопуть, построенный по временной и географической близости; он не доказывает фактический порядок движения или непрерывность маршрута.

### 5. HTML-клиент

`map.html` загружает `points_<год>.json` через `fetch`, проверяет координаты и отображает маркеры с кластеризацией Яндекс Карт. Для каждой точки доступна ссылка на файл и ссылка, открывающая `photo-path.html` с параметрами года и индекса точки. На карте отображаются линии по сегментам `paths`.

`photo-path.html` загружает тот же JSON, находит путь, содержащий индекс выбранной точки, и показывает его снимки последовательно. Навигация доступна кнопками и клавишами ←/→. Если точка не входит в сегмент (например, нет подходящей пары), страница показывает только её. Изображение отображается, если формат поддержан браузером; ссылка на исходный файл остаётся доступной.

HTML-файлы используют внешний API Яндекс Карт. Поэтому для карты требуется интернет; доступность API и требования к ключу зависят от настроек/условий Яндекса и окружения. В клиентском коде предусмотрена обработка неудачной загрузки JSON.

## Известные ограничения и ошибки обработки HEIC/HEIF

Поддержка расширения в списке файлов **не гарантирует**, что Pillow сможет декодировать сам файл. HEIC/HEIF — контейнерные форматы, кодеки и варианты метаданных в них различаются. В стандартной установке Pillow часто не умеет открывать HEIC/HEIF, поэтому возможны ошибки `UnidentifiedImageError`, сообщения об отсутствии декодера или ситуация, когда EXIF/XMP недоступны. Тогда GPS/дата не извлекаются; дата может перейти на `mtime`, а точка — попасть в категорию без GPS.

Рекомендуемый вариант — установить плагин и зарегистрировать его до открытия изображений:

```bash
python -m pip install pillow-heif
```

В начале `photo_map.py` после импорта Pillow добавьте:

```python
from pillow_heif import register_heif_opener
register_heif_opener()
```

Поддержка зависит от версии `pillow-heif`, Pillow и библиотек декодирования, доступных для вашей ОС. На Windows могут потребоваться совместимые бинарные колёса/зависимости. Некоторые HEIC-файлы содержат метаданные в нестандартном месте или без доступных EXIF-тегов; установка плагина сама по себе не гарантирует извлечение GPS и даты. Для проверки сначала запустите обработку на нескольких примерах HEIC и изучите предупреждения в stderr.

Также браузер может не показывать HEIC как изображение даже при успешном чтении метаданных Python. В этом случае исходный файл доступен по ссылке, но для превью потребуется преобразовать копию снимка в JPEG либо использовать браузер с поддержкой HEIC.

## Другие ограничения и рекомендации

- В коде отключён лимит Pillow `Image.MAX_IMAGE_PIXELS` для панорам. Это позволяет открывать очень большие изображения, но снимает защиту от чрезмерного расхода памяти; обрабатывайте только доверенные файлы.
- Псевдокоординаты генерируются случайно, поэтому при повторной генерации могут измениться.
- Ссылки на фото работают, если каталог снимков доступен браузеру по HTTP и структура каталогов совпадает с относительными путями в JSON. Для удалённого GitHub Pages локальные фотографии автоматически не загружаются; их нужно отдельно публиковать и учитывать приватность/объём.
- `map.html` и JSON должны обслуживаться одним локальным HTTP-сервером; `file://` не подходит для `fetch`.
- Координаты проверяются в HTML перед отображением, но JSON считается локальным доверенным входом. Не размещайте непроверенные данные и пользовательские файлы на публичном сервере без дополнительной защиты.
